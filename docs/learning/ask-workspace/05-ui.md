# Ask your workspace — P5 UI

## What we built

Replaced InsightPanel placeholder with question form and structured answer view. The panel opens from existing selection action, and sends request only after user presses Ask. Evidence buttons focus matching artifacts on canvas; API still searches whole workspace.

## Why it exists

Before this packet, Nook had backend answer logic but no way for a user to ask through the app. The button makes model use intentional, while loading, error, and empty states show what is happening. Showing answer, key points, evidence, and unresolved issues keeps source material visible beside generated text.

## New AI concept(s) in plain English

- **Grounded answer** means answer returned with references to saved artifacts. Backend checks evidence ids against its retrieved set, and this UI shows those references. Grounding lowers unsupported output risk but does not prove every sentence true.
- **Loading state** is UI shown while request is in progress. Here it says “Searching workspace evidence…” after Ask, while disabling duplicate requests.
- **Empty state** is UI shown before results exist. Here it prompts user to ask a question; a backend no-evidence answer remains visible as an answer with no evidence list.
- **Error state** is UI shown when request fails. The panel shows safe backend message, such as missing API key or temporary generation failure.

Example: user selects a few cards about launch, opens InsightPanel, and asks “What happened with launch?” No request goes out until Ask is pressed. Existing endpoint receives workspace id and question; backend may return evidence from anywhere in workspace, not only selected cards. This is a known scope limit accepted for P5.

## Line-by-line walkthrough of the 2-3 most important functions

### `handleSubmit`

```ts
async function handleSubmit(event: FormEvent<HTMLFormElement>) {
    event.preventDefault();
    const trimmedQuestion = question.trim();
    if (!trimmedQuestion || selectedCount === 0 || isLoading) return;

    setIsLoading(true);
    setError(null);
    setAnswer(null);
    try {
        setAnswer(await askWorkspace(workspaceId, trimmedQuestion));
    } catch (requestError) {
        setError(requestError instanceof Error ? requestError.message : "Could not get an answer. Try again.");
    } finally {
        setIsLoading(false);
    }
}
```

- Form submit gives us browser event, so type it as a form event.
- Prevent default page reload; React keeps panel state in place.
- Trim whitespace so spaces alone are not a question.
- Exit if question empty, nothing selected, or request already running. This is a UI guard; backend still validates requests.
- Turn on loading and clear old result/error so previous answer cannot look current.
- Call API only here, after explicit submit. Selecting artifacts itself never calls Gemini.
- On failure, show API's safe message when available; otherwise show stable fallback copy.
- `finally` always clears loading, whether request succeeds or fails.

### `goToEvidence`

```ts
function goToEvidence(artifactId: number) {
    const artifact = artifacts.find((item) => item.id === artifactId);
    if (!artifact) return;

    camera.centerOn(
        toRenderPosition({ x: artifact.x, y: artifact.y }),
        { width: window.innerWidth, height: window.innerHeight },
    );
    onEvidenceClick(artifactId);
}
```

- Evidence id is a number because Artifact ids are numeric.
- Find matching artifact in current workspace state; do nothing if it is no longer available.
- Convert stored canvas coordinates to render-world coordinates. Camera works in render coordinates.
- Center camera on card using current viewport dimensions.
- Tell Home to select card and close panel, so user can inspect source.

### API request error handling

```ts
const error = (data as { error: unknown }).error;
if (typeof error === "string" && error.trim()) {
    throw new Error(error);
}
if (
    typeof error === "object" && error !== null &&
    "message" in error && typeof error.message === "string" && error.message.trim()
) {
    throw new Error(error.message);
}
```

- Server APIs use both `{ error: "Workspace not found" }` and `{ error: { message: "..." } }` shapes.
- The shared API helper accepts a non-empty string or nested message, then falls back to HTTP status text for malformed bodies.
- Before this follow-up, the string shape became `Error(undefined)` and left Ask panel with blank alert.
- The workspace service still sends workspace id in URL and question in JSON body; shared helper attaches auth token.
- Existing endpoint searches full workspace. Selected ids are not sent or enforced by backend.

## How it can go wrong

1. **No API key configured.** Backend returns 503; panel shows configuration message and remains usable after restart/config fix.
2. **Provider timeout or invalid output.** Backend returns safe 502; panel shows retry guidance and clears loading state.
3. **Evidence is outside selected cards.** Existing endpoint retrieves from whole workspace; panel says answer uses workspace evidence, and evidence links focus actual returned cards. P5 does not claim selection-limited answers.

## Interview questions

1. **How do you prevent selection from triggering unexpected cost?** — “Selection only opens the panel. I call the endpoint inside form submit, after the user presses Ask.”
2. **How do you keep model output inspectable?** — “I render evidence ids and reasons beside answer and key points, and let user jump to source card.”
3. **Does answer use only selected cards?** — “No. Existing endpoint searches the workspace. UI makes that clear; limiting retrieval to selected ids needs a backend contract change.”
